# 01. 시스템 아키텍처 및 핵심 개념

## 1. 핵심 개념 정의 및 관계

지식 기반 엔터프라이즈 AI 시스템은 **KM**, **RAG**, **AI Agent**, **Fine-tuning**의 4가지 핵심 축으로 구성됩니다.

| 기술 요소 | 정의 | 역할 | 직장인 비유 |
| :--- | :--- | :--- | :--- |
| **KM (Knowledge Management)** | 지식의 수집, 구조화, 축적, 권한 관리 체계 | 원본 데이터 및 지식의 원천 저장소 | 회사의 체계적인 **중앙 서고 / 아카이브** |
| **RAG (Retrieval-Augmented Gen)** | 지식 저장소에서 실시간으로 관련 문서를 검색하여 LLM에 제공하는 기법 | 최신 지식 검색 및 정확한 팩트 기반 추론 | 서고에서 필요한 문서를 1초 만에 찾아주는 **전문 검색 도구** |
| **AI Agent** | 목표를 스스로 분석/계획하고, 도구를 활용해 완수하는 자율 실행 주체 | 의사결정, 다단계 검색 조율, 외부 툴/API 실행 | 지시를 받아 스스로 계획하고 실행하는 **똑똑한 실무 담당자** |
| **Fine-tuning (학습)** | 도메인 특화 데이터로 모델의 가중치를 미세조정 | 사내 양식, 전문 어휘, 고유 톤앤매너 내재화 | 사내 신입 교육을 통해 익히는 **업무 기본 소양 / 말투** |

## 2. 통합 Agentic RAG 시스템 계층 구조

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. Presentation & Application Layer (사용자 및 배포)                  │
│    - No-Code Web Studio / Chat UI / Slack Bot / REST API Gateways       │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
┌───────────────────────────────────▼────────────────────────────────────┐
│ 2. AI Agent Orchestration Layer (두뇌 및 판단)                         │
│    - 목표 분해 및 계획 (Planning)                                      │
│    - 조건 분기 & 도구 호출 (Tool Execution)                           │
│    - 자체 검증 및 환각 평가 (Self-Correction & Reflection)             │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ (도구로 RAG 호출)
┌───────────────────────────────────▼────────────────────────────────────┐
│ 3. RAG Pipeline Layer (지식 검색 및 추론 엔진)                         │
│    - 질의 재작성 (Query Rewriter) / 다단계 심층 검색 (Multi-hop)       │
│    - 하이브리드 검색: Dense Vector(임베딩) + Sparse BM25 (키워드)      │
│    - 재순위화: Cross-Encoder / BGE-Reranker                             │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ (어디서 검색하는가?)
┌───────────────────────────────────▼────────────────────────────────────┐
│ 4. KM & Data Storage Layer (지식 저장소)                               │
│    - 파싱/정제된 Markdown, 구조화된 표(Table), 메타데이터 태그         │
│    - Vector DB (Chroma, Qdrant, Milvus) & 키워드 인덱스                │
│    - 원본 문서 저장소 (HWP, PDF, PPTX, Notion 등)                      │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ (주기적 데이터 가공)
┌───────────────────────────────────▼────────────────────────────────────┐
│ 5. Training / Fine-tuning Layer (지속적 학습 엔진)                     │
│    - LLM 기반 합성 QA 데이터셋 생성 (Self-Instruct)                     │
│    - SFT / LoRA / QLoRA 도메인 미세조정 파이프라인                     │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. 엔드-투-엔드 데이터 흐름

```
[사용자 복합 요청]
  │ 예: "지난달 AI 세미나 발표자료와 최신 제안서 비교해서 요약 보고서 작성해줘"
  ▼
[AI Agent: 계획 수립]
  ├── 1단계: 세미나 자료 검색 ──> [RAG] ──> [KM Storage (PPTX 파싱본)]
  ├── 2단계: 최신 제안서 규격 검색 ──> [RAG] ──> [KM Storage (HWP/PDF 파싱본)]
  ├── 3단계: 추출된 두 맥락을 비교 분석하여 보고서 초안 생성
  └── 4단계: (선택) 사내 이메일 또는 슬랙 API 툴 호출하여 결과 전송
```

## 4. 왜 4개 요소를 유기적으로 결합해야 하는가?

1. **KM 없는 RAG/Agent**: 데이터의 품질과 버전이 보장되지 않아 잘못된 정보(Garbage In, Garbage Out)를 추론하게 됨.
2. **RAG 없는 Fine-tuning**: 문서가 수정될 때마다 막대한 비용을 들여 재학습해야 하며, 최신 정보 반영과 출처 인용이 불가능함.
3. **Agent 없는 단순 RAG**: 복잡한 다단계 질문이나 문서 간 교차 비교를 수행하지 못하고 단순 단답형 응답에 그침.
4. **결론**: **KM(기반 데이터) + RAG(실시간 검색) + Agent(자율 추론) + Fine-tuning(도메인 어휘/스타일)**이 결합될 때 완벽한 엔터프라이즈 AI 시스템이 완성됩니다.
