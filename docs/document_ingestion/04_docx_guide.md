# 📝 04. MS 워드 문서 (DOCX / DOC) 계층 파싱 및 임베딩 가이드

본 문서는 계약서, 제안서, 연구보고서 등 워드 문서(`.docx`, `.doc`)를 **AI Agentic Knowledge Hub**에 고품질로 인덱싱하기 위한 기술 가이드입니다.

---

## 1. 워드 문서의 특징 및 추출 전략

* **제목 아웃라인 계층 (Heading 1, 2, 3)**: 워드 문서는 목차 계층 구조가 잘 잡혀 있으므로, 단락의 스타일(`style.name.startswith('Heading')`)을 파악하여 Markdown `#`, `##`, `###`로 매핑합니다.
* **표(Table) 및 셀 병합**: 워드 내 복잡한 표를 Markdown 표로 완벽 복원합니다.
* **구형 `.doc` 처리**: LibreOffice Headless 엔진을 통해 `.docx`로 무손실 자동 변환 후 파싱합니다.

---

## 2. 사용 도구 및 엔진

* **`python-docx`**: 본문 단락, 인라인 서식(굵게, 기울임), 표 객체(`docx.table.Table`), 문서 속성(작성자, 수정일) 추출
* **LibreOffice Headless**: `.doc` ➔ `.docx` 또는 `.pdf` 변환

---

## 3. 계층형 마크다운 변환 예시

```markdown
# 1. 총칙

## 제1조 (목적)
본 규정은 사내 정보자산의 안전한 관리를 목적으로 한다.

## 제2조 (적용 범위)
본 규정은 전 임직원 및 파견 인력에게 적용된다.

### [표: 자산 분류 등급표]
| 등급 | 정의 | 관리 책임자 |
| --- | --- | --- |
| 1등급 | 대외비 및 핵심 지적재산 | 본부장 |
| 2등급 | 사내 한정 정보 | 팀장 |
```

---

## 4. Hub 등록 및 활용

* **청킹 전략**: `Heading 2` 또는 `Heading 3` 단위의 섹션 청킹 (Section-based Chunking)
* **메타데이터**:
  ```json
  {
    "source": "정보보안_표준계약서.docx",
    "file_type": "docx",
    "section_title": "제2조 (적용 범위)",
    "hierarchy": "1. 총칙 > 제2조 (적용 범위)"
  }
  ```
