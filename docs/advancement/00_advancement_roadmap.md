# 00. 고도화 로드맵 총괄

본 디렉토리(`docs/advancement/`)는 현재 구현된 **AI Agentic Knowledge Hub**를 다음 단계로
확장하기 위한 개발 문서를 담습니다.

기존 `docs/` 하위 문서들이 **"현재 시스템이 어떻게 동작하는가"** 를 설명한다면,
본 디렉토리는 **"무엇이 아직 없고, 어떤 순서로 무엇을 만들 것인가"** 를 다룹니다.
따라서 각 문서는 반드시 다음 세 가지를 명시합니다.

1. **현재 상태(As-Is)** — 코드에서 실제로 실행·확인된 사실만 기술
2. **목표 상태(To-Be)** — 설계 및 인터페이스 정의
3. **작업 항목** — 구현 순서와 선행 의존성

## 고도화의 핵심 명제

> **지식을 "검색용 벡터"가 아니라 "정규화된 레코드"로 저장하고,
> RAG 인덱스와 학습 데이터셋을 모두 그 레코드의 파생물로 만든다.**

현재는 파싱 결과가 곧바로 ChromaDB에 청크로 들어가고 원본 구조는 어디에도 남지 않습니다.
이 상태에서는 ML/DL 학습 데이터를 뽑으려면 **검색 전용 저장소인 벡터DB를 역으로 긁어야 하는**
왜곡된 구조가 됩니다. 따라서 지식 원천을 별도 계층으로 분리하는 것이 모든 확장의 전제입니다.

## 작업 순서 및 의존 관계

```
[완료] DOCX 표 유실 결함 수정        ← 데이터 원천 신뢰성 확보 (모든 작업의 전제)
    │
    ▼
[02] KnowledgeStore 구축            ← 없으면 이후 전부가 벡터DB에 종속됨
    │
    ├────────────────┬───────────────┐
    ▼                ▼               ▼
[03] Embedding    [04] Dataset    [05] A2A / Registry
     공급자 분리        Builder          (02 완료 후 병렬 가능)
    │                ▲
    └────────────────┘
      학습 모델을 추론에 재투입하는 순환 완성
```

**02번을 최우선으로 두는 이유**: KnowledgeStore가 없으면 DatasetBuilder도, A2A로 노출할
지식 조회 스킬도 모두 ChromaDB를 직접 참조하게 됩니다. 그러면 나중에 저장소를 교체하거나
학습 파이프라인을 붙일 때 전면 재작성이 필요해집니다.

## 착수 전 선행 조치 (완료됨)

고도화에 착수하기 전, **파서가 표(Table)를 유실하는 치명적 결함**을 먼저 해결했습니다.
데이터 원천이 손상된 상태에서 KnowledgeStore를 구축하면 그로부터 파생되는 RAG 인덱스와
학습 데이터셋이 **전부 오염**되기 때문입니다.

상세 내역은 **[01_current_state_audit.md](./01_current_state_audit.md)** 의 2절을 참조하십시오.
